# Бункер

Браузерная онлайн-игра на выживание и переговоры. Мест в убежище меньше,
чем людей: каждый раскрывает свои характеристики и убеждает остальных,
что нужен именно он.

Чистый JavaScript и CSS. Ни одного фреймворка, сборщика и внешней
библиотеки — только шрифты и, по желанию, SDK Firebase с CDN.

---

## Запуск

Модули ES не работают по протоколу `file://`, поэтому нужен любой
локальный сервер:

```bash
python3 -m http.server 8000
# или
npx serve .
```

Откройте `http://localhost:8000`.

Сразу после запуска игра работает в **локальном режиме**: комнаты живут
между вкладками одного браузера. Этого достаточно, чтобы проверить все
правила — откройте три вкладки и сыграйте сами с собой.

## Подключение сети

Для игры между устройствами нужен Firebase Realtime Database.

1. Создайте проект на [console.firebase.google.com](https://console.firebase.google.com).
2. Добавьте **Realtime Database** (не Firestore).
3. Настройки проекта → Ваши приложения → Web → скопируйте конфигурацию.
4. Вставьте её в `src/net/config.js`.
5. В разделе Rules базы задайте:

```json
{
  "rules": {
    "rooms": {
      "$code": {
        ".read": true,
        ".write": true,
        ".validate": "newData.hasChildren(['code'])"
      }
    }
  }
}
```

Игра сама определит, что конфигурация заполнена, и переключится в
сетевой режим. Если Firebase окажется недоступен, она молча вернётся
к локальному транспорту вместо того, чтобы упасть.

Правила выше открыты для всех — это нормально для игры с друзьями.
Для публичного размещения добавьте анонимную авторизацию и ограничьте
запись полями своего игрока.

## Архитектурные решения

**Детерминированная генерация.** Персонажи, бункер и катастрофа
выводятся из зерна `код комнаты + время старта`. Все клиенты приходят
к одинаковому результату независимо, поэтому по сети передаются только
действия, а не содержимое карт. Переподключившийся игрок восстанавливает
партию целиком.

**Плоские патчи.** Движок возвращает изменения вида
`{'game/phase': 'vote'}`. Этот формат напрямую ложится в multi-path
update Firebase, поэтому одновременные ходы разных игроков не затирают
соседние поля. Локальный транспорт понимает тот же формат.

**Устойчивость к обрывам.** Идентификатор игрока хранится на устройстве,
выход не удаляет игрока из комнаты, а лишь снимает флаг присутствия.
Firebase через `onDisconnect` сам помечает отключившихся, а при
восстановлении связи флаг поднимается обратно.

**Ручная разблокировка стола.** Если два игрока сделали ход в одну и ту
же секунду, ни один из них не видел ход другого и фаза могла не
переключиться автоматически. В таком случае ведущему показывается
кнопка перехода — стол не может застрять.

**Производительность.** Анимируются только `transform` и `opacity`.
Частицы фона создаются один раз и дальше живут на CSS, JavaScript в
кадре не участвует. На слабых устройствах включается экономный профиль:
пыль, зерно и часть слоёв отключаются. Экраны перерисовываются только
при изменении значимой части состояния, поэтому фоновое сердцебиение
игроков не вызывает лишней работы.

## Проверка правил

```bash
node tools/simulate.mjs
```

Прогоняет партии на 3–16 игроков: проверяет смену фаз, подсчёт голосов,
завершение игры, отсутствие потерянных или дважды изгнанных участников
и совпадение генерации между клиентами.

## Что осталось на усмотрение игроков

Спец-карты (обмен характеристиками, вето, принудительное вскрытие)
движок показывает текстом, но не исполняет автоматически — момент
применения участники согласуют между собой, как в настольной версии.
Обсуждение тоже идёт голосом или в стороннем чате: встроенного чата нет.
